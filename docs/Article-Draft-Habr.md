# Как мы перестали бояться крашей и полюбили причинные графы

*Черновик статьи для Habr / VC.ru — черновик, не финальный текст.*

## Зачем ещё один браузер

Nexus Monach Browser — приватный браузер для Windows на WebView2 с полностью
локальным AI (перевод страниц, синхронный дубляж видео, голосовые оповещения)
и многослойным анонимным маршрутом. Проект GPLv3, всё открыто: [репозиторий][repo].

Статья не про фичи. Она про то, как маленькая команда перестала гадать по
логам и научилась **доказательно диагностировать отказы** — и как это
изменило культуру разработки.

## Проблема: молчаливые отказы

Классическая боль десктоп-приложения: у пользователя «что-то не работает»,
а у тебя — ничего. Пустые catch-блоки (у нас их было 139), краш без стека,
«браузер просто закрылся».

Мы прошли путь из четырёх шагов, и каждый следующий был бы невозможен
без предыдущего.

## Шаг 1. Breadcrumbs — следы хлеба

Каждый значимый этап оставляет запись в кольцевом буфере последних 50
событий. Краш-рапорт забирает их с собой. Дёшево (ConcurrentQueue), но
момент аварии перестал быть чёрным ящиком.

## Шаг 2. Причинные графы вместо стеков

Стек говорит «где», но не «почему». Мы строим направленный граф:
breadcrumbs + **системные события Windows** (EventID 1000 — краши процессов,
EventID 4101 — сбросы видеодрайвера) + само исключение. Рёбра —
«предшествовало/вызвало». Корневая причина вычисляется обходом вверх
по цепочке «вызвало».

Реальный пример из продакшена: `RenderProcessUnresponsive` (браузерный
рендер завис) за 7 секунд до `UCEERR_RENDERTHREADFAILURE` (смерть потока
отрисовки WPF) — граф показал связь, которую никто бы не увидел в логах.

Бонус: рапорт выгружается в Mermaid — GitHub рендерит диаграмму прямо
в issue.

## Шаг 3. Дым вместо крика

 ARP-страж писал «MAC шлюза изменился!» каждые 5 секунд. Причина?
Страж **не читал ARP-таблицу** — он сравнивал MAC-адреса собственных
сетевых адаптеров машины (Ethernet → туннель → vEthernet — «подмена!»).

Мораль: детектор, который не читает первоисточник, стреляет по соседям.
Переписали на `GetIpNetTable` (P/Invoke) с состоянием на каждый интерфейс
отдельно — ложные срабатывания исчезли как класс.

## Шаг 4. Оповещай один раз, доказывай всегда

Правило «один голос на атакующего за сессию» превратил поток паники
в сигнал. А каждое срабатывание ARP-детектора теперь собирает улики:
старый и новый MAC + полный снимок ARP-таблицы атакуемого интерфейса.
