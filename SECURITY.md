# Безопасность

## Цепочка доверия поставки и обновлений

- Nexus Guardian проверяет ECDSA-подпись (P-256) релизного манифеста и SHA-256
  критических файлов до запуска. Полная проверка дополнительно хэширует крупные
  модели; критическое несовпадение блокирует запуск, а некритическое включает
  safe mode. Официальные сборки доверяют только встроенному ключу
  (`GUARDIAN_OFFICIAL`); девелоперские — ключу-файлу рядом со сборкой, и границы
  доверия не пересекаются.
- Автообновление скачивает `nexus-core.zip` (76 МБ) из latest-релиза GitHub,
  сверяет SHA-256 архива с digest релиза, распаковывает в изолированный стейджинг
  и повторно проверяет подписанный манифест уже распакованного дерева. Применение
  атомарно (copy-then-move) и происходит только после выхода браузера и лаунчера;
  после применения установленный каталог верифицируется снова. Отказ применения
  пишется в `Updates/apply-error.log` и не ломает текущую установку.
- Манифест целостности лёгкой установки допускает отсутствующие файлы AI-пакетов
  (записи `Pending`): их отсутствие — не нарушение, а после доставки они
  проверяются теми же хешами, что и ядро. Обновление ядра не удаляет
  доставленные нейросети.
- Сетевая поставка AI (OnlinePack) идёт по подписанному ECDSA-манифесту
  `release-manifest.json`; каждый пакет сверяется с SHA-256 из манифеста, при
  несовпадении файл стирается и перекачивается. Компрометация зеркала не даёт
  подсунуть полезную нагрузку — сломается подпись или хеш.
- Установщик (Nexus.Setup) встраивает публичный ключ доверия при сборке, ставит
  ядро в профиль пользователя без прав администратора, регистрирует протокол
  `nexus://`, запись удаления и ярлыки; деинсталлятор удаляет их и файлы.
  Приватный ключ подписи в установщик и сборку не попадает.

## Анонимный стек

- Режим След направляет трафик через локальный Tor (SOCKS5 `127.0.0.1:9051`);
  мосты obfs4/snowflake/meek/webtunnel генерируют torrc без участия оболочки.
  Порт-страж гасит WebRTC-ICE, mDNS/SSDP и DNS в обход Tor на уровне браузера.
- Релейный мост работает только как bridge и никогда как exit-узел:
  `ExitPolicy reject *:*` зашита в генератор torrc и покрыта тестами. Адрес
  моста публикуется в BridgeDB (`BridgeRelay 1`), а не в публичный консенсус;
  Nickname санитизируется по алфавиту Tor. Браузер честно сообщает, когда
  порты моста недоступны извне (NAT без проброса).
- Теневая загрузка аудиодорожки для перевода видео принимает только публичные
  HTTPS-адреса: loopback, приватные и зарезервированные диапазоны, а также
  не-http(s) схемы отклоняются до соединения (SSRF-защита).
- Сетевой Дозор слушает только порты-приманки на этой машине и не сканирует
  чужие серверы; ответы обманщика не содержат данных пользователя.
- Порт-щит закрывает правила файрвола через один повышенный вызов PowerShell
  со скриптом-файлом (без строковых команд в аргументах). Правила именованы
  `Nexus Leak Guard — …`, действуют до выхода браузера и снимаются при выходе;
  пользовательские службы (RDP, SMB, VNC) автоматически не закрываются.

## Поведение браузера
- Почтовый канал Guardian запускается только вручную для выбранного локального
  рапорта. Пароль Proton, SMTP-token и OAuth-credential в браузере отсутствуют.
  JSON шифруется AES-256-GCM, а одноразовый ключ — отдельным RSA-3072 OAEP-SHA256
  открытым ключом владельца. Закрытый ключ рапортов нельзя хранить в репозитории,
  GitHub Actions, release-архиве или на машинах тестировщиков.
- Движок используется в режиме Evergreen и должен регулярно получать исправления Microsoft.
- Ошибки TLS-сертификатов не обходятся и не принимаются автоматически.
- Доступ сайтов к чувствительным возможностям требует разрешения пользователя.
  Разрешение относится только к точному HTTPS-origin верхней страницы;
  сторонние iframe, HTTP и внутренние страницы автоматически отклоняются.
- Взаимодействие локальных страниц с приложением принимается только от точного
  HTTPS-origin `https://nexus.local`: стартовая страница и страница результатов
  имеют отдельные списки допустимых сообщений.
- Встраивание произвольных host objects в страницы отключено.
- Стандартные Chromium DevTools не содержат Nexus AI: отдельное расширение и
  HTTP loopback-мост для него удалены. F12 и Ctrl+Shift+I открывают штатное окно
  DevTools текущего WebView2 без собственного дерева сайта.
- Расширения импортируются в управляемую локальную папку. Устанавливайте только проверенные расширения: они способны читать и изменять содержимое сайтов в пределах запрошенных ими разрешений.
- Встроенная блокировка трекеров не заменяет антивирус, обновления Windows и осторожность при загрузке файлов.
- Nexus Veil использует отдельный InPrivate-профиль WebView2 и одноразовый
  локальный ID процесса. В приватном окне принудительно действуют Strict
  Tracking Prevention, DNT/GPC, удаление известных tracking-параметров,
  запрет сохранения паролей и автозаполнения. ID не передаётся сайтам.
- Строка сетевой личности не выполняет внешний IP-запрос и не обещает
  анонимность: DIRECT раскрывает обычный маршрут, наличие VPN-интерфейса не
  доказывает прохождение трафика через него, а учётные записи и поведение могут
  связать даже разные сетевые сеансы.
- Карта получателей запросов хранит в памяти вкладки только host, счётчик,
  WebView2 resource kind и факт наличия заголовков Cookie/Referer/Origin. Значения
  заголовков, тела запросов и полные URL не записываются.
- Стандартные Chromium DevTools являются инструментом разработчика и могут
  показывать DOM, cookies, токены и другие секреты открытой страницы.
- URL загрузки сохраняется только как origin без query, fragment и userinfo.
  SHA-256 рассчитывается локально, а Authenticode проверяется через Windows
  WinVerifyTrust без сетевого обращения. Исполняемые файлы, архивы и документы
  с активным содержимым требуют отдельного подтверждения перед открытием даже
  при наличии доверенной подписи.
- AI-компоненты release-сборки находятся в папке `AI` и не загружаются во время работы. Runtime-код проверяется CI на отсутствие известных внешних адресов моделей.
- HTTP-клиенты локальных AI-runtime не используют proxy и redirect, принимают
  только loopback IP literal и устанавливают сокет непосредственно к нему.
  `llama-server` требует случайный ключ текущего процесса, переданный через
  окружение; Whisper использует новый случайный inference-маршрут при каждом
  запуске. Ключи, маршруты и порты не записываются в рапорты.
- Crawl Engine автоматически читает только публичные HTTPS-адреса на
  стандартном порту. DNS разрешается через выбранный DoH-провайдер и проверяется
  внутри обработчика соединения, после чего сокет открывается к точному
  проверенному IP; локальные и служебные диапазоны, metadata endpoints и
  DNS-rebinding блокируются. При пользовательском proxy адрес назначения
  предварительно проверяется Nexus, но окончательное соединение и повторное
  разрешение имени остаются частью доверенной границы proxy.
- Строгий DoH включён по умолчанию и не переходит на системный DNS при ошибке.
  Cloudflare используется без категорийной фильтрации; опциональный Quad9
  блокирует известные вредоносные домены. Сетевой слой не применяет общий
  фильтр 18+, фильтрацию слов/категорий или принудительный SafeSearch. Временный
  DNS-кэш находится только в памяти процесса и не записывается в журналы Nexus.
- HTTPS-first сначала обновляет верхнеуровневый HTTP-переход до HTTPS. Ошибка
  сертификата не обходится; незашифрованный переход возможен только после
  отдельного подтверждения пользователя для одной навигации.
- Dependabot еженедельно создаёт обновления NuGet и GitHub Actions. Патчи автоматически объединяются только после успешной Windows-сборки; защищённая ветка должна требовать workflow `Verify Windows build`.
- Обновления `llama.cpp`, `whisper.cpp` и весов моделей не объединяются как обычные файлы: для них требуется сверка лицензии, контрольной суммы и тестов качества/безопасности модели.
- Nexus Guardian проверяет ECDSA-подпись релизного манифеста и SHA-256 критических
  файлов до запуска. Полная проверка дополнительно хэширует крупные модели;
  критическое несовпадение блокирует запуск, а некритическое включает safe mode.
- Crash Vault по умолчанию локален. Отчёт очищается от URL, истории, DOM, cookies,
  токенов, введённых значений, сетевого отпечатка, аудио и снимков экрана. В коде
  нет встроенного GitHub-токена или стороннего telemetry SDK.
- GitHub access token (fine-grained PAT, Issues: Read & Write на один репозиторий)
  запрещено помещать в раздаваемую сборку. Токен вставляется тестировщиком в
  настройках и хранится только в Windows Credential Manager его учётной записи.
  Даже при утечке токен даёт лишь право создавать issues в одном репозитории
  и отзывается одним кликом. Crash Vault отправляет только санитизированные
  отчёты; дубликаты схлопываются в комментарии к одному issue по сигнатуре.
- Приватный ECDSA-ключ Guardian и Authenticode PFX никогда не хранятся в git.
  Процедура выпуска описана в `docs/Nexus-Guardian.md`.

При обнаружении уязвимости не публикуйте пароли, cookies, токены или личную историю в открытом отчёте.
